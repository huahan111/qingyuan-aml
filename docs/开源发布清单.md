# 开源发布清单（GitHub）

> 发布动作由仓库作者本人执行；本清单是操作步骤与发布前检查项。

## 一、发布前检查（已由 2026-10-24 整改完成）

- [x] 敏感信息终扫：身份证/银行卡/手机号正则无真实命中（`backend/scripts/check_compliance.py` 全过）；
      全仓库无 API Key / 密码 / .env（.gitignore 已排除 .env、数据库与备份）
- [x] 演示人名为虚构角色（README 与页面均已声明合成数据）
- [x] LICENSE（MIT + 演示项目补充声明）、README_EN.md、docs/PRD.md 已入库
- [x] git 历史分阶段（基线 → P1 缺陷修复 → P2 审计链 → P3 CDD → P4 配置 → P5 文档），无大文件
- [x] 删库重建一致；测试全绿（run_all 六套件）

## 二、发布步骤

1. 在 GitHub 新建仓库，建议名 `qingyuan-aml`，描述：
   `QingYuan AML — a demo MVP of an anti-money-laundering monitoring platform: rule engine with regulation traceability, 62-element STR reports, tamper-evident SHA256 audit chain, and an honest AI boundary. 中文文档见 README.md。`
2. 本地推送：
   ```bash
   cd 清源MVP
   git remote add origin git@github.com:huahan111/qingyuan-aml.git
   git push -u origin master --tags
   ```
3. 仓库设置：
   - About 勾选 Releases，topics 建议：`anti-money-laundering` `regtech` `compliance` `fastapi` `sqlite` `chinese` `aml` `fintech`
   - 默认分支保护可不设（个人项目）；建议开 Issues
4. 发布 Release v1.0.0-demo：Tag `v1.0.0-demo`，标题 `演示级 MVP（第四轮迭代）`，
   正文可直接引用 PRD §10.13（缺陷修复清单 + 新增能力 + 测试口径）
5. 简历/一页纸中的在线链接指向部署地址（部署见 docs/部署指南.md），
   GitHub 仓库链接作为"代码与测试留痕"入口

## 三、发布后维护建议

- 每次对外演示前：`python3 tests/run_all.py` 确认全绿；演示环境开 `QINGYUAN_READ_ONLY=1`
- 收到 Issue 先分类：bug（复现→修复→回归测试）/ 边界问题（先查 PRD §10 是否已声明）
- 不要在公开仓库放置任何真实业务数据或机构信息
