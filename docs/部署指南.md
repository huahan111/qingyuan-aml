# 部署指南

三种部署形态按可用环境选择。**公开部署的硬前提：只读模式（`QINGYUAN_READ_ONLY=1`）**——本系统无登录鉴权（演示定位，如实标注），只读模式下所有写接口 403、审计链保持不可变，访客仍可自助完成研判、生成报告草稿、CDD 查询与审计链校验。

## 形态一：Docker（推荐，任何有 Docker 的服务器）

```bash
docker compose up -d --build     # 默认只读模式，端口 8000
curl http://127.0.0.1:8000/api/health   # 验证：read_only 应为 true
```

- SQLite 与审计链持久化在 named volume `qingyuan-data`；首次启动自动建库（8 法规/239 条/17 规则/17 案例）。
- 换端口改 `docker-compose.yml` 的 ports（如 `"80:8000"`）。
- 公网正式暴露建议前置 Nginx/Caddy 做 HTTPS（Caddy 两行自动证书）：

```
demo.example.com {
    reverse_proxy 127.0.0.1:8000
}
```

## 形态二：裸机 run.sh（本机演示/内网）

```bash
./run.sh                          # 127.0.0.1:8000，可写（本机演示用）
QINGYUAN_READ_ONLY=1 QINGYUAN_HOST=0.0.0.0 ./run.sh   # 内网只读公开
```

要求 Python ≥ 3.10（run.sh 有版本守卫）。

## 形态三：托管平台（WorkBuddy 等）

已按 WorkBuddy 平台核实（2026-10-24）：①支持**常驻 Python 进程**（FastAPI + SQLite 为官方支持形态）；②平台**只注入 `PORT`**，不能自定义环境变量（支持随项目携带 `.env`，main.py 会自动加载且平台注入的变量优先）；③只能用**平台分配的子域名**；④沙箱**无密钥注入**——公网版只能跑 mock 预生成诊断（默认即是），Live 模式需本地或自有服务器配置 `OPENAI_API_KEY`。

适配已完成：**启动命令用 `python3 backend/main.py`（不要用 run.sh）**，代码默认即平台安全态——

| 平台约束 | 代码适配 |
|---|---|
| 只注入 PORT | 端口优先级 `PORT` > `QINGYUAN_PORT` > 8000，自动读取 |
| 无法设环境变量 | 默认**只读**（fail-closed）+ 默认 `0.0.0.0`；如需覆盖，随项目放 `.env`（已存在的环境变量优先） |
| 无密钥注入 | 默认 mock Provider（零 token、预生成校验结果），页面如实标注 |

部署后自查：`/api/health` 返回 `read_only: true`；`POST /api/admin/reset-demo` 应 403。

## 形态四：内部试用（带登录鉴权）

在形态一/二/三基础上加 `QINGYUAN_AUTH=1`：三角色登录（jingban/fuhe/shenpi，演示口令 见后端启动日志）、写接口角色校验、审计链操作人实名、三级签字"谁登录谁签本级"。适合给一家机构内部小范围真实试用（导入脱敏数据跑研判）。多实例或需重启保活会话时，配置固定 `QINGYUAN_SESSION_SECRET`。

## 部署后自查清单

- [ ] `/api/health` 返回 200，且 `read_only: true`（公开部署时）
- [ ] 手工 POST `/api/admin/reset-demo` 应返回 403（只读生效）
- [ ] 台账页点「完整性校验」→ 审计链完整（公开只读下为空链或初始链，均应 ok: true）
- [ ] CDD 页示例号一键直查正常（查询在只读下放行，审计不记录属预期）
- [ ] 简历/作品页上的链接与本部署形态描述一致（真 MVP / 快照）
