# 演示视频说明

- 成片：`docs/media/demo-video.mp4`（3 分 44 秒，1600×900）
- 在线播放：<https://qingyuan-aml-demo.app.workbuddy.host/demo-video.mp4>

## 怎么做的

配音为本人录音（7 段，按口播稿顺序），录屏不是手工录制，而是脚本驱动：

1. **截图层**：Playwright 打开本地运行的 MVP 页面，按固定节拍（2.5 帧/秒）连续截图，
   时间戳由节拍器保证，不依赖浏览器录屏器的帧时间戳；
2. **操作层**：与截图并行，按配音的逐句时间戳调度点击、输入、滚动
   （例如旁白说到「我点开溯源」时，画面在同一秒展开溯源面板）；
3. **合成**：ffmpeg 把截图序列 + 7 段人声（响度统一 +12dB，段间直接拼接）合成 MP4。

脚本：`tools/make_demo_video_v4.py`（需 Python 3.14 + playwright + ffmpeg，且本机存在 seg0~seg6 录音）。

```bash
python3.14 tools/make_demo_video_v4.py   # 输出 ../清源AML_演示视频_人声版_v3.mp4
```

## 口播稿（v3.0）

**开场**：大家好，我是冯宇。我在工行网点做了 8 年，柜员和客户经理都干过。上班的时候也做过一些反洗钱相关工作，遇到了很多问题。于是我把这些一线经验做成了一套系统，也就是我的清源反洗钱智能监测平台。平台内的所有数据全部是合成的演示数据，AI 用的是预生成诊断，也就是提前生成好、人工校验过的结果。

**一条预警的溯源**：现在我给大家做一个演示，我会点开一条预警，看它到底是什么情况。比如这条：八笔现金存款，每一笔都贴着 5 万这条线，就差一点点，系统判定是拦截。这就是典型的拆分交易，规避 5 万元大额申报，被系统抓出来了。那系统是怎么发现的？重点看这里——我点开溯源，规则是怎么触发的、三号令是哪一条、官方类型是怎么说的、处罚是什么，对应的原文都放在这里，方便溯源。判断不是模型说的，是法规写的。

**写可疑交易报告**：研判完之后要写可疑交易报告。可疑交易报告中有 62 项官方要素，这边都已罗列齐全。其中填的内容有合成的数据、有关键信息，也有 AI 写的判别，像第 21、22 项的分析就是 AI 写的。没接官方代码集的地方就留空，专岗去填。

**台账与审计链**：台账这块，每一步操作都会进审计链。操作层面只能加、不能改，数据库层面也做不了修改。每条记录都带服务器时间戳，还带着上一条的哈希，一环扣一环。为了防篡改，还有完整性校验——谁要是拿到数据库文件做了修改，就过不了这个完整性校验。

**名单筛查**：名单筛查是打分制的，我输入「组织」，它不会直接冻结，只提示疑似，转人工。真命中了才会冻结。这里说明一下：正式使用要接入权威名单数据源，比如联合国制裁名单、人行下发的名单，或者 World-Check 这类商业名单库，定期更新。名单更新之后，还能一键回溯筛查所有存量客户，这是监管检查必看的环节。名单这块现在是演示数据。

**尽职调查**：尽职调查这页，输入身份证号或者企业的统一社会信用代码，就能做对应的尽职调查和客户身份识别。数据源这块，后面会接相应的 API 和监管系统，现在仅做演示。我点这个示例号，查这家供应链公司：成立不到一年，集群注册，没有社保记录，属于高风险。身份证号、统一社会信用代码，走的都是国标校验算法。

**评级与收尾**：最后是客户风险评级，4 个维度实时算，预警结果会动态写回评级里。报告报送后面要接人行的报文系统，现在仅做演示，相关代码、测试、方案现已全部开源，链接在页面。我是冯宇，谢谢你的观看。
