# 清源AML · 反洗钱智能监测平台 MVP

> 每一条交易研判结论，都可溯源到法规条文。
> 演示系统 · 所有数据均为脱敏合成 · 仅供学习交流

## 系统架构

```
前端（HTML + CSS + 9 个 JS 模块，蓝白配色，9 个页面：工作台 / 全流程 / 预警 / 名单 / 大额 / CDD / 评级 / 规则 / 报送）
  └─ HTTP ─→ FastAPI 后端（backend/main.py）
                ├─ 演示数据读取层 case_store.py：读 backend/data/demo_cases.json
                ├─ 规则域 domain/rules/：base_rules.py（R001–R008）+ typed_rules.py（R009）+ cdd_rules.py（R017）
                │                     registry.py 注册表 · engine.py 执行 · 阈值读 rules.params
                ├─ AI 诊断层 ai_diagnosis.py：Mock/Live 双 Provider
                ├─ 三向分流：放行 / 拦截 / 人工复核
                ├─ 案例召回 domain/cases/：特征提取 + 字符 n-gram TF-IDF + 结构特征，输出 top-k 相似案例
                ├─ 报告域 domain/report/：elements.py（62 项 JSON）+ builder.py + text.py + deadline.py
                └─ SQLite 参考库（backend/data/qingyuan.db）
                     ├─ 8 份法规 239 条条款（含 FTS5 trigram 中文检索）
                     └─ 17 条规则定义（其中 10 条可执行，R011–R016 规划中）

演示案例不进 SQLite：
  backend/data/demo_cases.json —— 17 条合成案例（dataset=demo v1.1）
  SQLite 的 cases 表用于已定性案例库：报送完成后自动沉淀，供相似案例召回
```

## 三分钟演示路径

**A. 工作台（单案研判）**

1. **打开首页** → 先看到工作台看板：演示案例统计、近 7 日交易量、高频规则 TOP5、今日待办、快捷入口；下方才是案例库（可疑拦截 8、灰区 6、放行 3）
2. **点击 BLOCK-01「大额转入分批转出」** → 查看客户画像与 8 笔贴线现金流水（每笔 49,050–49,500 元，紧贴 5 万申报线）
3. **点击「开始研判」** → 规则引擎命中 R002，AI 诊断为「官方第1-1类 疑似非法汇兑型地下钱庄（『规避』识别点）」，分流结果**拦截**
4. **点击「展开溯源」** → 逐层展开：R002 触发逻辑 → 3号令第五条/第十一条原文 → 官方对照表类型1-1『规避』识别点原文 → 对应央行处罚事由
5. **点击「一键生成 STR 初稿」** → 62 项要素对照表（系统带出 / 演示预填 / AI 生成第 21、22 项 / 本笔不适用）+ 中英双语正文 + 可修订 + 三级授权签字
6. **点击 EXCLUDE-01「批发货款归集后支付供应商」** → R003 命中但 AI 依据合同、发票、固定上下游排除 → 分流为「命中-排除留痕」；点「确认排除并沉淀负样本」后，案例库新增 `DIS-EXCLUDE-01`，确认理由、操作人与时间可查，规则有效性里 R003 的排除案例由演示期望值变为已沉淀记录

**B. 全流程演示（7 步闭环）**

系统扫描 → 预警筛选 → 研判处置 → STR 生成 → 预览签署 → 三级授权（经办 / 复核 / 审批）→ 报文报送人行 + 回执归档。
每一步都走真实后端接口；扫描日志中的案例数、规则数来自数据库，不是写死的文案。

**C. 规则页看联动**

完成一次报送后进入「监测规则配置」：能看到刚沉淀的 `LIB-` 案例、该规则的有效性（命中/确认/排除）、以及官方类型矩阵里的案例支撑数。这展示的是“报送结果如何反哺规则与案例库”，不是额外功能演示。

## STR 报告与签字授权

报告不是只读的，按真实业务流程设计：

1. **格式核对**：打开报告先做结构核对——62 项齐全、四部分完整、无空值；依据人民银行令〔2016〕第 3 号附件，正式报送需转换为 XML 报文。
2. **人工修订初稿**：报告生成后**默认进入编辑模式**，可直接修改 62 项要素与中英正文；点「保存修订」后版本号递增、修改项标「人工修订」，并留下旧值/新值/修改人/时间记录。
3. **确认初稿**：核对修改结果后点「确认初稿 · 进入签字授权」，先出现二次确认「是否确认报告内容真实、准确、完整」，避免误签。
4. **三级授权**：经办 → 复核 → 审批，逐级授权；每级须选择授权方式（指纹识别 / 人脸识别 / 授权卡 / 通行密钥 / 刷员工卡）。
5. **留痕**：姓名、工号、岗位编号、授权方式、时间写入报告签字区，并进入报文 `AuditInfo`；签字后报告不可再修改。
6. **提交是独立动作**：三级授权完成只代表「报告已定稿」，报告状态为「已签字待报送」；必须再点「提交报送」并二次确认，才生成回执、进入已报送状态。签字不等于提交。
7. **复核 / 审批预览**：复核、审批岗在签字前可点「预览报告内容」，只读查看 62 项要素、中英正文、修订记录，以及上一级已签记录；关闭预览自动回到授权界面，再决定通过或退回。

> 中英双语说明：英文正文为结构化模板——I/II/IV 段随本案数据动态生成，III 段（分析判断）按结论变化（拦截=存在重大偏离 / 人工复核=存在待核验点 / 放行=未发现重大偏离）并指向中文第 21–22 项；不是逐句翻译，对外演示时如实说明即可。

> 报送路径说明：MVP 演示的是经办机构直接向人民银行反洗钱监测分析中心（CAMLMAC）报送。网点→支行→分行→总行的内部流转，以及按案例类型走不同监管口，属于后续路由设计，当前未实现；内部流转与法定 STR 报送是两条不同的链路，不能混为一谈。

### 上报台账

每次「提交报送」成功后，自动写入 SQLite 运营表 `submissions`（与演示案例 JSON 分开）：

- 回执号、报告编号、案例、客户、报送时间、报告版本
- 经办 / 复核 / 审批（姓名 + 工号）
- 完整签字记录（通道、方式、设备、相似度、时间）
- 报告快照（62 项要素 + 中英正文）

左侧「上报台账」页按报送时间倒序展示，支持：

- 统计卡：累计上报、今日上报、覆盖案例、最近回执
- 关键词搜索（回执号 / 报告号 / 案例 / 客户 / 经办）与日期区间筛选
- 逐条查看回执、三级签字、修订记录与退回记录
- 点任意记录可打开归档报告，只读查看当时的 62 项内容、版本与签字，不可修改
- **更正报告**：基于原记录生成新草稿，重新走三级授权；新记录标记「更正报告」并关联原回执，原记录自动标记「已更正」
- **导出 CSV**：按当前筛选结果导出，带 UTF-8 BOM，Excel 可直接打开

报告编号格式为 `STR-YYYYMMDD-案例号-时分秒毫秒+流水`，同一案例同一天重复生成也不会重复；台账写入时再做一次编号冲突检查。

演示环境不会再出现「报完就消失」；记录持久化在 `backend/data/qingyuan.db`，重启后仍在。

## 报告核对口径

打开报告时的核对区做三件事：

- 结构核对：62 项齐全、四部分完整、第 1–24 项必填无空值
- 字段格式检查：交易金额、开户/交易日期、证件号码、15 位报告机构编码
- 时限展示：发现之日起 5 个工作日（跳过周末与法定节假日、计入调休上班日；`backend/data/holidays.json` 已内置 2026 年国办发明电〔2025〕7 号安排，未配置节假日时会时限说明中如实标注）
- 导出要素 XML 草稿：按 62 项分组输出，供报文开发对接；**不是正式 CAMLMAC 报文，未经 XSD 校验**

**边界**：当前版本未接入 CAMLMAC XSD 与官方代码集，报告仅为演示草稿；正式报送前必须补齐报文层与通道层。完整的四层符合性口径、已实现/部分实现/未实现清单、前置条件与 Roadmap，见 PRD 第十章「MVP 实现台账」。

### 修改权限与状态机

| 状态 | 能否修改 | 谁可签字 | 可执行动作 |
|---|---|---|---|
| 草稿 | 经办可改 | 经办 | 编辑、经办签字 |
| 待复核 | 锁定 | 复核 | 签字通过；或退回经办修改 |
| 待审批 | 锁定 | 审批 | 签字通过；或退回经办修改 |
| 已签字待报送 | 锁定 | — | 提交报送；或撤回本级签字 |
| 已报送 | 锁定 | — | 仅查看回执与归档 |

- 修改权限跟状态绑定，不是全局开关；一旦经办签字，内容立即锁定。
- 复核/审批发现问题的正确动作是「退回修改」，不是直接改；退回后签字全部清空，报告回草稿，重走授权。
- 每次修订记录旧值、新值、修改人、时间，版本号递增（v1 AI 初稿 → v2 人工修订）。
- 签字可撤回，但只能撤回本级且不能跳过下一级；已报送不可撤回。

### 指纹 / 人脸授权逻辑

授权通道与可用方式：

| 通道 | 可用方式 | 适用场景 |
|---|---|---|
| 网点柜面 | 指纹识别 / 授权卡 / 刷员工卡 | 柜台办理，指纹仪 `FP-NJ-0231` |
| 移动端 | 人脸识别 / 手机指纹 / 通行密钥 | 外出或远程复核，摄像头 `MOB-CAM-01` |
| OA 通行密钥 | 通行密钥 / 授权卡 | 内部审批流单点登录 |

采集流程：

1. 选通道 → 选方式 → 进入采集态（指纹：按压指纹仪；人脸：正对摄像头）。
2. 采集完成 → 比对/活体检测 → 返回设备号、相似度（如指纹 98.6%、人脸 97.2%）。
3. 失败可重新采集；关闭授权框会清空未完成的采集，不产生签字。
4. 授权记录写入：通道、方式、设备号、相似度、姓名、工号、岗位、时间；报文 `AuditInfo` 同步。

> 演示环境模拟采集与比对；真实系统需接指纹仪 SDK、摄像头活体检测或统一身份认证，不接受手工点选。

## 客户尽职调查（CDD）接入

页面「客户尽职调查」可实际发起两类查询，**只查询、不落库、不保存证件号**：

| 场景 | 现状 | 真实环境怎么接 |
|---|---|---|
| 对公工商尽调 | 内置 3 家合成企业（成立年限、集群注册、经营异常、受益所有人等维度） | **企查查 / 天眼查开放平台**：按次计费，基础工商约 1 元/次，综合风险接口最高约 6 元/次；需注册开放平台账号、申请 Key、报备调用场景 |
| 个人身份核验 | GB 11643 校验位算法（真实算法）+ 证件有效期判断 + 模拟联网核查 | 两条路：①**人行"联网核查公民身份信息系统"**——2007 年与公安部建成，覆盖全国银行网点，银行机构通过本行前置系统提交姓名+身份证号，返回一致/不一致与照片；**仅对银行业金融机构开放，不是公开 API**。②**持牌商用二要素/三要素核验**（腾讯云、阿里云市场等）：按次计费，需实名与场景报备 |

**设计原则**：Provider 抽象，未配置外部数据源时 `available()` 为 False，接口直接报"未接入"——**不会用模拟结果冒充真实核查**。接入只需实现 `backend/services/cdd.py` 里对应 Provider 的 `lookup_enterprise` / `verify_identity`（签名、参数、错误处理已在基类约定），页面与接口无需改动。

```bash
# 预留接入位：配置后由你的实现替换内置模拟库
QCC_API_KEY=xxxx    # 企查查开放平台 Key（未配置时页面显示"未接入"）
```

### 交易数据字段

每笔交易三个字段分治，不混用：

| 字段 | 含义 | 取值 |
|---|---|---|
| `type` | 交易类型，只描述“钱怎么走” | 10 个枚举：转账收入/转账支出/现金存入/现金支取/跨境收入/跨境支出/结汇收入/购汇支出/代发工资支出/代扣代缴支出 |
| `purpose` | 交易摘要/用途（银行摘要或客户申报） | 工资、货款、增值税、学费、赡家款、佣金… |
| `summary` | 交易附言，客户自己填的备注 | 可空；合同编号、平台结算单号、USDT… |

规则的方向判定用显式集合 `IN_TYPES/OUT_TYPES/CROSS_TYPES`（`domain/rules/common.py`），不靠子串猜测；金额计量一律走 `amt()`（取 `amount_cny`，缺省回落 `amount`）。`/api/intake` 对三个字段都做归一化与校验。

### 外币折算汇率

交易支持多币种：`currency` 记原币，`amount_cny` 记折人民币；规则命中与报告金额一律按折人民币计量。折算用**取整估算值**（不是实时牌价），来源是 `backend/data/fx_rates.json`，界面案例详情的汇率条与数据金额共用这一份，观众可以当场手算核对：

| 币种 | 演示折算汇率 | 真实中间价（2026-10-21） | 说明 |
|---|---|---|---|
| USD | **1 美元 = 7 元** | 6.7192 | 取整便于心算，略保守 |
| EUR | **1 欧元 = 7.5 元** | 7.5197 | 偏差 <0.3%，×7.5 等于先乘 7 再加半倍 |

例子：GREY-02 的 USD 40,000 × 7 = ¥280,000；GREY-03 的 EUR 2,000 × 7.5 = ¥15,000。真实环境应取交易发生日的中间价，并把取汇率这件事留痕。

**合规提示**：涉及个人信息的核验要遵守《个人信息保护法》最小必要原则——查询必须留痕（谁、什么时间、查了什么）、不得缓存完整证件号（本实现只回显掩码）、对外提供核验服务需取得相应资质。项目当前**不落库**，正是为了不越过这条线。

## 规则与类型覆盖

- 规则库定义 17 条，MVP 可执行 10 条（R001–R009 + CDD 条线身份不明规则 R017；R010 套现商户等类型化规则为规划中）；**10 条可执行规则均有演示案例支撑**（R003 两条），规则有效性页可直接看到命中/确认/排除；R010–R016 标注「规划中」，需接入商户、报关、关系网络等数据后启用。
- 「监测规则配置」页提供官方类型覆盖矩阵（官方 12 类 + 行内归纳 4 组 + 无法归类出口），逐类标注已覆盖 / 部分覆盖 / 规划中 / 未覆盖，不把规划中算作已覆盖，也不把行内归纳算作官方类型。
- 当前明确未覆盖：4 走私（缺报关数据）；部分覆盖：1-1（BLOCK-01 贴线分拆）、1-2（BLOCK-03 过账 / EXCLUDE-01 排除留痕）、6 集资（BLOCK-02）、11 赌博（BLOCK-04）。
- CDD 相关 2025 年 11 号令 52 条已入法规库，R017 已引用第二十八条/第八条/第四十一条；灰区案例尚未建立条款级引用，页面已如实标注。

## 设计红线（继承自 PRD）

- AI 只碰结论不碰原始数据；规则引擎先行输出结构化特征
- 疑似涉罪类型强制对齐官方对照表 12 类清单（1-1 ~ 12），保留「无法归类」出口（非交易型可疑行为，如客户身份不明，走 11 号令第四十一条）
- 名单拦截（R005）不走 AI：先限制后核验，24 小时内人工复核
- 会话数据不残留：服务无状态，案例/法规库只读
- 免责：演示系统，数据脱敏合成；内置案例诊断为预生成人工校验结果（页面已如实标注）
